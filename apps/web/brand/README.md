# brand

Sources for the raster brand assets. Nothing here is deployed: `public/` is what
ships, this directory is what `public/` was generated from. The rationale for
every choice lives in `docs/design.md`.

| Source | Output | Size |
|---|---|---|
| `og.html` | `../public/og.png` | 1200 x 630 |
| the mark inlined below | `../public/apple-touch-icon.png` | 180 x 180 |

`../public/favicon.svg` is hand-written and has no source step. It is the one
copy of the mark that ships as vector; `src/components/Wordmark.tsx` holds the
same path for the app, drawn with design tokens instead of literal hex so it
follows the theme.

## Regenerate

Headless Chrome rasterises both files. There is no build step and no
dependency: these are committed artifacts, regenerated by hand when the mark or
the one-line thesis changes.

```
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$CHROME" --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=1 \
  --window-size=1200,630 --screenshot="apps/web/public/og.png" \
  "file://$PWD/apps/web/brand/og.html"
```

For the touch icon, point the same command at a 180 by 180 page containing only
the mark, with `--window-size=180,180`.

## If you change the mark

Three files carry it and all three have to move together, or the tab icon and
the header stop matching:

1. `apps/web/public/favicon.svg`
2. `apps/web/src/components/Wordmark.tsx`
3. `apps/web/brand/og.html`, then regenerate `public/og.png`
